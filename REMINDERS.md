# Neovim: рабочая шпаргалка

`Leader` — **пробел**. `Space ff` значит последовательно нажать пробел, `f`, `f`.
Регистр важен: `dS` и `ds` — разные команды. Если не указано другое, клавиши
нажимаются в normal mode: сначала `Esc` или `jk`. На Mac для F-клавиш иногда нужен `fn`.

## Самое нужное

| Клавиши | Действие |
|---|---|
| `Space ff` | Найти файл в проекте |
| `Space fw` | Найти текст по файлам проекта |
| `Space fb` | Найти открытый буфер |
| `Space e` | Перевести фокус в дерево файлов |
| `gd` / `Ctrl+o` | Перейти к определению / вернуться |
| `K` | Документация; на остановке DAP — значение переменной |
| `Space ca` | Code actions |
| `Space rn` | Переименовать символ через LSP |
| `Ctrl+s` | Сохранить файл |
| `Space wK` | Показать список сочетаний WhichKey |

## Поиск файлов и текста

| Клавиши | Действие |
|---|---|
| `Space ff` | Поиск файлов относительно рабочей директории |
| `Space fa` | Также скрытые и игнорируемые файлы |
| `Space fo` | Недавно открывавшиеся файлы |
| `Space fz` | Нечёткий поиск строк в текущем буфере |
| `Space fw` | Поиск текста в проекте, требует `rg` |
| `/текст` + `Enter` | Поиск вперёд в текущем файле |
| `?текст` + `Enter` | Поиск назад |
| `n` / `N` | Следующее / предыдущее совпадение |
| `*` / `#` | Поиск слова под курсором вперёд / назад |
| `Esc` | Убрать подсветку совпадений в normal mode |

Telescope: имя файла стоит первым, превью находится снизу и занимает 70% высоты.
`Ctrl+n` / `Ctrl+p` выбирают результат, `Enter` открывает его,
`Ctrl+d` / `Ctrl+u` прокручивают превью без перевода фокуса.
`Ctrl+v` открывает результат в вертикальном split, `Ctrl+x` — в горизонтальном.
Для выхода — `Esc` до normal mode, затем `q`.
Если ищется не тот проект, проверь `:pwd` и при необходимости выполни `:cd путь`.

В дереве nvim-tree: `Enter` открывает файл/папку, `/` ищет по видимым строкам,
`n` переходит к следующему совпадению. `S` открывает поиск узла дерева;
`f` включает live-фильтр, `F` сбрасывает его, `g?` показывает справку.
`Ctrl+n` показывает/скрывает дерево. `Space ff` работает и из дерева.

| `Tab` / `Shift+Tab` | Следующий / предыдущий буфер в normal mode |

| `gg` / `G` / `42G` | Начало файла / конец / строка 42 |
| `Ctrl+o` / `Ctrl+i` | Назад / вперёд по истории переходов |
| `s` / `S` + два символа + метка | Leap: быстрый переход вперёд / назад |
| `v` / `V` | Выделить символы / строки |
| `y` / `p` | Скопировать выделение / вставить; используется системный буфер |
| `u` / `Ctrl+r` | Отменить / повторить изменение |
| `Space /` | Закомментировать строку или выделение |
| `;` | Начать команду, как `:` |
| `:w` / `:q` / `:wq` | Сохранить / закрыть окно / сохранить и закрыть |

`Space h` / `Space v` — открыть терминал снизу / сбоку.
В терминале `Ctrl+x` выходит в normal mode, `i` возвращает ввод в терминал.

### Запуск Bash-скриптов с curl

Открой `.sh` / `.bash` файл и нажми **`Space rr`** или введи **`:RunScript`**.
Файл сохранится и целиком запустится через `bash`; вывод появится в терминале
снизу и останется после завершения. Запускаются все команды файла, не только
строка под курсором. Для файлов без расширения нужен `:set filetype=sh`.

Рабочая папка — корень Git-проекта; если его нет — ближайший `go.work`/`go.mod`,
иначе папка скрипта. Переменные окружения наследуются от Neovim;
`.env` автоматически не загружается, его нужно подключить в самом скрипте.

`Ctrl+c` останавливает выполняющийся скрипт в terminal mode.
Чтобы повторить: `Ctrl+x`, `Ctrl+k` к исходному файлу, затем `Space rr`.
Новый запуск заменяет прошлый вывод. Если предыдущий скрипт ещё работает,
повторный запуск переключает к нему, не отправляя запросы второй раз.
Нижнее окно можно закрыть через `Ctrl+x`, затем `:q`.

## Go и gopls

Название сервера — **gopls**. Он даёт переходы, переименование, подсказки,
автодополнение, code actions и диагностику. Открывай проект с его `go.mod`
или `go.work`; сам `gopls` должен быть установлен и доступен Neovim.

| Клавиши / команда | Действие |
|---|---|
| `gd` / `gD` | Определение / объявление |
| `gI` | Реализации интерфейса или метода |
| `gr` | Места использования символа |
| `Space D` | Определение типа |
| `K` | Сигнатура и документация; во время остановки — DAP hover |
| `Space rn` | Переименовать символ и его использования |
| `Space ca` | Доступные исправления и рефакторинги; работает и с выделением |
| `Space ds` | Список диагностики, `:lclose` закрывает его |
| `[d` / `]d` | Предыдущая / следующая диагностика |
| `Space fm` | Форматирование вручную |
| `:ConformInfo` | Какой форматтер используется и доступен ли он |
| `:checkhealth vim.lsp` | Проверка подключения LSP |
| `:Mason` | Управление установленными инструментами |

При сохранении Go форматируется через `gofmt`, затем запускается
`golangci-lint`, если установлен. Организация импортов автоматически не включена;
смотри доступные действия в `Space ca`.

В insert mode: `Ctrl+Space` вызывает автодополнение, `Ctrl+n/p` выбирают вариант,
`Enter` подтверждает (может выбрать первый), `Ctrl+e` закрывает список.
`Tab` / `Shift+Tab` выбирают подсказки или переходят по полям сниппета.
Если `Ctrl+Space` перехватывает macOS, автодополнение обычно появляется при вводе.

## Отладчик Go

Нужны `go` и `dlv` в PATH. Сначала открой файл пакета `main`, например
`cmd/service/main.go`, затем `F5` → **Debug current package**.
Этот вариант запускает каталог текущего файла: не запускай им обычный пакет
с обработчиками. **Debug workspace** подходит, если запускаемый пакет находится
в корне проекта. Рабочая директория конфигураций — `${workspaceFolder}`.

| Клавиши | Действие |
|---|---|
| `Space db` | Поставить / удалить брейкпоинт |
| `Space dB` | Условная точка, например `userID == 42` |
| `F5` | Начать отладку или продолжить с остановки |
| `F10` | Следующая строка без входа в вызванную функцию |
| `F11` / `F12` | Войти в функцию / выйти из текущей функции |
| `Space dt` | Отладить Go-тест под курсором |
| `Space dq` | Завершить отладку |
| `Space du` | Показать / скрыть нижнюю панель |
| `Space dr` | Открыть REPL: вывод программы и вычисление выражений |
| `Space dS` | Показать стек вызовов во всплывающем окне |
| `Space dl` / `:DapBreakpoints` | Список брейкпоинтов |

**Несколько HTTP-запросов в одной сессии:** запрос → остановка → изучить
переменные → `F5` один раз → следующий запрос → новая остановка.
`Space dq` для этого не нужен. Если программа уже работает, повторный `F5`
открывает меню управления сессией; его можно закрыть, не завершая процесс.
Во время долгой остановки клиент HTTP может дождаться таймаута — тогда нужен новый запрос.

Красные `B` / `C` — точки; красная `▶` и зелёный фон — место текущей остановки.
Справа от кода — краткие превью значений до 100 символов. После продолжения они очищаются.

**Ховер:** поставь курсор на переменную → `K`; ещё раз `K` — войти в окно.
`j/k` выбирают поле, `Enter` раскрывает/сворачивает структуру, `q` / `Esc` закрывают.
`Space de` вычисляет переменную или выделенное выражение вроде `data.Items[0]`.
Внутри ховера `y` копирует значение, `Y` — всю строку:
`Title = "Привет"` → `y`: `Привет`, `Y`: `Title = "Привет"`.
JSON-совместимые кавычки и escape-последовательности строк декодируются.
Копируется отображаемый текст: обрезанное Delve значение не восстанавливается.

В списке брейкпоинтов: `j/k` — выбор, `t` — выключить/включить без потери условия,
`o` — перейти к коду, `d` — удалить включённую точку, `q` / `Esc` — закрыть.
Выключенные точки сохраняются в текущем экземпляре Neovim, не в Git.

Если нет остановки: проверь запускаемый пакет, вывод в REPL, адрес/порт запроса
и ветку кода. Не каждый HTTP-запрос проходит через выбранный форматтер.
`verified = true` в DAP-логе означает, что Delve принял точку.
Пути логов: `:lua print(vim.fn.stdpath("cache") .. "/dap.log")`
и соседний `delve.log`; там могут быть данные приложения, в Git их не добавлять.

## Тесты, Git и обслуживание

| Клавиши | Действие |
|---|---|
| `Space tn` / `Space tf` | Запустить ближайший тест / тесты файла |
| `Space tl` | Повторить последний запуск тестов |
| `Space to` / `Space tp` | Вывод текущего теста / общая панель вывода |
| `Space ts` / `Space tq` | Сводка тестов / остановить тесты |
| `Space gt` / `Space cm` | Статус Git / история коммитов через Telescope |

`:Lazy` управляет плагинами; `:Lazy restore` восстанавливает версии из
`lazy-lock.json`. `:checkhealth` помогает искать проблемы окружения.
После изменения конфигурации проще перезапустить Neovim.

Конфиг находится в `~/.config/nvim`; тема — `lua/themes/islands-dark.lua`.
Сохранить изменения на личный GitHub:

```sh
cd ~/.config/nvim
git status
git add .
git commit -m "Описание изменений"
git push
```

Личный email и SSH-ключ настроены локально для этого репозитория; вручную
переключать рабочий Git не нужно. На другом компьютере автор коммитов и доступ
настраиваются заново: `.git/config` и SSH-ключи не входят в репозиторий.
