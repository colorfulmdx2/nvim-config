# Работа с конфигурацией Neovim

Этот репозиторий — личный конфиг Neovim для Go-разработки, основанный на
NvChad v2.5 и lazy.nvim. Пользователь переходит с GoLand: важны удобная
отладка, понятная навигация и компактный интерфейс. Отвечай по-русски.

## Источники истины и структура

- `init.lua` — загрузка lazy.nvim, NvChad и пользовательских модулей.
- `lua/plugins/init.lua` — спецификации плагинов, ленивые загрузки и клавиши тестов/DAP.
- `lua/mappings.lua` — общие клавиши поверх `nvchad.mappings`.
- `lua/options.lua`, `lua/autocmds.lua` — пользовательские опции и автокоманды.
- `lua/configs/lspconfig.lua` — LSP на API Neovim 0.11: `vim.lsp.config` / `vim.lsp.enable`.
- `lua/configs/conform.lua`, `lint.lua` — форматирование и линтинг.
- `lua/configs/dap.lua` — Go/Delve, панели, маркеры, превью значений и список точек.
- `lua/configs/debug_hover.lua` — контекстная клавиша `K`.
- `lua/configs/dap_value_colors.lua` — подсветка литералов в значениях dap-ui.
- `lua/configs/dap_copy.lua` — копирование значений из dap-ui.
- `lua/chadrc.lua`, `lua/themes/islands-dark.lua` — тема и пользовательские акценты.
- `lazy-lock.json` — зафиксированные версии плагинов; хранить в Git.
- `REMINDERS.md` — краткая инструкция пользователя; обновлять при изменении клавиш и сценариев.

Поведение складывается из локальных настроек и настроек установленного NvChad.
Перед изменением проверь обе части и версии из lock-файла. Дистрибутив плагинов
находится под `stdpath("data") .. "/lazy"`; его можно читать, но изменения вносить
в этот репозиторий, а не в установленные плагины или скомпилированный кэш base46.

## Правила изменений

- Делай изменения в пределах запроса, сохраняй уже сделанные пользователем правки.
- Используй `opts` для расширения настроек NvChad и отдельные модули для логики.
- Не обновляй плагины и lock-файл заодно с несвязанными правками.
- Сверяй клавиши с NvChad и буферными mapping: `<Space>ds` — диагностика,
  `<Space>dS` — стек; `<Space>rn` в LSP-буфере — переименование символа.
- Сохраняй ленивую загрузку; обычный `K` не должен сам загружать отладчик.
- Lua-стиль определён `.stylua.toml`: два пробела, двойные кавычки, ширина 120.
- Новые автокоманды регистрируй в именованных группах с `clear = true`.
- Не записывай в конфиг локальные пути конкретных проектов, токены, SSH-ключи
  и рабочие данные. В примерах используй нейтральные значения.

## Поведение, которое нужно сохранять

- Telescope: максимальный размер, имена файлов перед путями, список сверху,
  превью снизу; `preview_height = 0.7`. Значение `1.0` означает одну ячейку,
  поэтому полный размер задаётся через `{ padding = 0 }`.
- Тема — локальная адаптация Islands Dark; цвета исходной схемы взяты из
  JetBrains. Сохраняй указание источника в файле темы.
- DAP: снизу только REPL с выводом программы, без постоянных Locals/Watches.
- Брейкпоинты красные; текущая остановка — красная стрелка и зелёная строка.
- На остановке `K` открывает значение, в остальное время — документацию LSP.
- В ховере сохраняются раскрытие полей, подсветка литералов, `y` для значения
  и `Y` для строки. Жёлтая подсветка изменившихся значений имеет приоритет.
- Копирование берёт отображаемый текст, а не заново загружает объект из Delve.
  Не обещай получение полной структуры, если адаптер обрезал значение.
- После успешного Go `continue` с `allThreadsContinued = true` сбрасывается
  состояние всех потоков. Это обход несовпадения состояний установленного DAP
  и Delve; удалять его только после проверки исправления в используемой версии.
- Форматирование при сохранении: `gofmt` для Go, `stylua` для Lua; линтер Go —
  `golangci-lint`. Автоматическая организация импортов отдельно не настроена.

## Проверка и Git

Для документации достаточно сверки с конфигом и `git diff --check`.
Для Lua сначала проверь синтаксис и загрузку затронутого модуля. Изменения окон
проверяй реальным открытием, а не только чтением таблицы `opts`. Например:

```sh
nvim -n --headless -i NONE '+lua require("lazy").load({plugins={"nvim-dap"}}); require("dapui").open(); vim.wait(100); require("dapui").close()' '+qa!'
```

Проверку Go-сервиса и HTTP-запросов проводи только в рамках задачи пользователя;
одна загрузка модулей не подтверждает работу настоящей сессии Delve.

В репозитории уже локально настроены личный автор и отдельный SSH-ключ.
Сохраняй эту изоляцию: не меняй глобальный Git/SSH и настройки рабочих проектов.
`origin` — личный `colorfulmdx2/nvim-config`, `upstream` — `NvChad/starter`.
Не добавляй `.nvimlog`, swap-файлы, логи отладчика и секреты.
